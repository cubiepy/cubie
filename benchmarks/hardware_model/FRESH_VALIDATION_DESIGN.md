# Fresh source-only heuristic validation design

This is a manifest-generation specification, not a prediction manifest,
native experiment or approval of a model. The compact selector is not
assumed to exist. Actions and source sizes are selected using generated
source, frozen hardware evidence and the selector's published rule only.
No historical measured winner, native register count, solver timing or
measured iteration count is an input to that selection.

## Evidence and coverage boundary

`POLICY_AXIS_INVENTORY_E1.md` documents 24 retained split-system/algorithm
pairs. That bank contains LU/BiCGSTAB but no MR, fixes the first five
groups full, and omits independent Newton False. Its native alias labels
are not source-equivalence proofs. The old ten-row holdout covers only
Lorenz, stage full/count1, local/shared and one requested partition.
Neither is the proposed validation design.

The required core rows are:

| Family | Algorithm representative | Inner solvers | Rows |
|---|---|---|---:|
| ERK | rk23 | none | 1 |
| DIRK | kvaerno3 | LU, MR, BiCGSTAB | 3 |
| FIRK | radau_iia_3 | LU, MR, BiCGSTAB | 3 |
| Rosenbrock | rosenbrock23 | LU, MR, BiCGSTAB | 3 |

These are the ten source identities in the frozen holdout manifest,
used as a coverage inventory, not as an action ranking. No numerical or
performance result is transferred among these rows. Validation of these
representatives does not automatically approve defaults for every
tableau within their families.

## Source fixtures: a bounded core and transfer check

For each of the ten rows, scan source descriptors from the existing
`build_chain(n, consts_per_eq, n_params=2)` generator. The predeclared
size domain is every integer20 through64; constants per equation are3
and8, as already used by the chain fixtures. These are experimental
inputs, not fitted model parameters. Hash the generator, emitted system,
constant payload, parameter grid and source options.

Select three native source fixtures per row:

1. Chain(n_low,3), immediately below a selected predicted hardware
   transition.
2. Chain(n_high,3), immediately above it, with n_high=n_low+1.
3. Chain(n_low,8), an intensity/constant-footprint companion at fixed
   state count.

This makes30 core source fixtures. A transition must be computed from
actual source descriptors under a fixed compiler/service hypothesis:
an allocation quantum changes feasible occupancy, a temporal instruction
reuse set crosses a named cache capacity, or a local/shared data path
crosses a named capacity or bank/occupancy condition. A change of the
predicted winner alone, with no corresponding resource explanation, is
not a hardware-crossing witness.

When there are multiple qualifying transitions, select the smallest
source integer n_low, then the canonical resource identifier and action
identities. Retain other crossings in the CPU ledger. This deterministic
rule is independent of timing, score magnitude and the historical
location of an empirical optimum. If no crossing exists in20..64, use
the endpoints20 and64 and label the pair `range_control_no_predicted_crossing`.
Never claim it tests a crossing or silently expand the size search after
seeing native outcomes. Missing source-model support is a recorded
coverage failure, not a reason to choose an easier measured winner.

The c8 companion changes arithmetic, constant traffic and numerical
dynamics. It is not a pure arithmetic-only perturbation. Record its
source operation mix, constant owners/bytes, Jacobian structure and
liveness; do not attribute its result to state count alone.

Add one Lorenz96(n_high) fixture per row, using the existing generator and
its own original source settings and parameter grid. This gives40 source
fixtures in the complete compact validation design. The extra ten check
transfer to a different RHS/Jacobian structure at the same state count.
Call them generator-transfer checks, not statistically unseen holdouts:
both generator families occur in prior research. A separate identity
inventory records whether each exact generated size/configuration had
any prior native observation.

Fabbri Radau3/LU and Radau5/LU are two separately labelled source-stress
regressions for transcendental work and larger tableau structure. They
retain the actual ANS override and their distinct Newton settings. Their
actions are generated by the same source rule. Historical exception
winner labels are not injected into the action choice. These two known
research cases are not fresh holdout evidence. The core ten rows remain
the explicit scope unless additional tableaus receive their own source
and validation coverage.

## A sparse policy mechanism panel

The legal levels are full, count1, count2, count4 and False; the historical
label0 means count1, never False. Runtime loop ownership determines which
axes exist. ERK has no Newton/Krylov axis; Rosenbrock LU has neither,
Rosenbrock iterative has its linear axis, and DIRK/FIRK iterative have
independent Newton and Krylov axes. Read actual cap values from each
constructed workload instead of borrowing a cap from another row.

At the n_low,c3 anchor only, include the following source-policy panel
with first six groups full unless the row explicitly varies stage:

- Every row: five stage levels, holding other groups fixed.
- DIRK/FIRK LU: five Newton levels, holding the other groups fixed.
- DIRK/FIRK iterative: the four full/count1 Newton/Krylov corners;
  independent False substitutions with the other axis full; and
  independent count2/count4 substitutions with the other axis full.
  This is ten Newton/Krylov pairs, not the25-level Cartesian product.
- Rosenbrock iterative: five levels of its actual linear-loop group.

After sharing the all-full baseline this is102 distinct unroll settings
across the ten anchor rows before any exact source-identity deduplication:
5 for ERK,9 for each DIRK/FIRK LU row,14 for each DIRK/FIRK iterative row,
5 for Rosenbrock LU and9 for each Rosenbrock iterative row. This panel
exists to test level semantics and independent iterative choices; it is
not repeated across all40 source fixtures.

Groups2–6 also enter the finite candidate pool. For each such group that
the selector changes or that produces a source resource crossing, retain
an otherwise identical one-group witness. A claimed group-wide rule
cannot be approved if no source/native witness exercises that group.
True source identity must include generated code, directive metadata,
compiler options and placement; equal model cost or old native alias
labels do not permit removing an action. False remains an independent
compiler directive even when a particular source replay has the same
number of operations.

The main fixture actions are the source baseline, the selector's frozen
choice and both members of its chosen resource-crossing witness. Their
set union has at most four actions per fixture. For range controls use
the source-selected nearest competing action, recording why it competes.
The baseline is a declared all-full/local source constructor, not a
historical timing winner. Include a separately identified baseline
duplicate for execution reproducibility; its identity never gives it a
second vote in regret or winner calculations.

Placement witnesses must compare actual source owners and whole aliases.
Add a local/shared pair only when both are source-feasible, including
bank layout, shared allocation, caller liveness and occupancy. Preserve
the exact binding of shared min4 bytes, 128-byte allocation quantum and
1024-byte driver reservation from the frozen target record. Codegen
register demand is the source allocation estimate; compiled registers
and local-frame sizes are validation outputs only.

The finite bundle pool is now explicit. A minimal execution panel can
be selected by exact set cover of the stated coverage requirements,
using number of unique actions as the primary objective and canonical
IDs as the tie breaker. Baseline/variant and low/high witnesses are
indivisible coverage bundles. No timing-derived weight is allowed. The
coverage matrix and proof of which requirements each retained bundle
satisfies belong in the manifest. This gives an auditable minimum
within the declared pool rather than an informal claim of universal
minimality. Missing support cannot be optimized away.

## Prediction freeze and validation boundary

The manifest generator has two data domains:

**Prediction domain:** exact source constructors and options; generated
source and workload descriptors; per-family/inner solver identities;
source liveness, operation forms, aliases, memory/instruction addresses;
frozen published hardware and microprobe service catalog; legal launch
geometry; compiler-form and cache-domain hypotheses; the compact
selector implementation, scores, ties and missing-service reasons.

**Validation domain:** new cubins/SASS, compiled attributes, actual launch
geometry and partition, output/status arrays, native iteration counters,
CUDA-event samples and diagnostics. These can test the freeze but cannot
change its candidates, work regimes, thresholds or constants.

Before native compilation, emit a fully resolved immutable manifest
containing all case/action IDs, generated-source hashes, default compiler
flags, exact grids/constants, expected signatures, requested geometry,
model/scenario/catalog hashes, every predicted score/tie and every
crossing witness. Record omitted source regimes and unsupported actions.
Predict across each source's own first-iteration/cap endpoints, with
Newton/Krylov independent, and with explicit per-call/warp regimes when
supported. Never fit a mask or iteration-frequency distribution from
native counters. A model that supports only coherent repeated warp
streams must identify that limitation; such a slice is not a full
solver default forecast.

Keep compiler alternatives common across all candidate actions. An
action may not choose the most favorable register form, cache domain or
partition after seeing its native result. Record the selector's declared
uncertainty policy, including all ties. Use accessed instruction identity
and temporal reuse under named line/domain assumptions; a whole reserved
code span is not an instruction-cache working set.

Freeze default compiler flags exactly. Source `contract=False` plus
final FMA false is a separately labelled arithmetic intervention. RK23's
bitwise equality under that intervention cannot validate a heuristic
under default compiler flags. Implicit contraction diagnostics are
likewise separate, whatever their eventual outcome. No transformed
diagnostic reference is copied into a default-compiler bank.

Use the source builders' original durations, grids and tolerances.
Choose a batch from source/hardware capacities sufficient for at least
two full waves, then verify the actual compiled geometry before timing.
For the existing target,262144 trajectories with128-thread blocks exceed
two full waves even at the hardware thread-capacity ceiling; this is a
source-independent launch-size choice, not a measured occupancy label.

Own-output determinism and raw SUCCESS are necessary but insufficient.
Before performance is admitted, each selected action must pass the
predeclared unchanged numerical comparison against the source baseline.
If the predicted action fails, that workload fails validation. Do not
choose a measured fallback or erase a failing challenger. A revised
numerical contract would need separate independent numerical evidence
and explicit approval; the current design makes no such revision.

After numerical admission, use the existing ab_gate paired ABBA protocol,
with compilation and array initialization/finalization outside CUDA-event
kernel intervals, full raw samples, prescribed idle gaps and exact
endpoint checks. A duplicate baseline tests execution reproducibility.
Iteration diagnostics and NCU/CUPTI captures occur separately and are
never prediction inputs. Incidental Solver verbose timing output is
retained but is not a deliberate timing bank or analysis input.

Actual shared partition must be checked as validation metadata. The
installed compatibility-module setter does not control the actual
dispatcher CUlibrary function. The later actual-function experiment also
observed a0 versus nonzero partition split, not six guaranteed physical
partitions. A requested percentage cannot be labelled an actual cache
size. Predictions must cover the declared possible partitions before
freeze; a native partition outside that set is a model/launch mismatch,
not permission to retune the prediction. Preserve the unresolved CUPTI
local0 versus actual-function40 discrepancy separately.

## Quarantine and presently unavailable outputs

An additional independent numerical-oracle panel tests default compiler
flags without relying on agreement between two policies. It does not
replace the required original Lorenz or Fabbri checks. Use actual coupled
linear systems with a source-frozen closed-form solution, for example
`y' = (-a I + B)y`, where B is strictly lower triangular with declared
bandwidth. Then
`y(t) = exp(-a t) * sum(k=0..n-1, t^k B^k/k!) * y(0)`.
The finite polynomial gives an independent oracle for the coupled
system; this is not a collection of independent scalar decays.

Use exactly representable FP32 source coefficients, such as a=1 and
band coefficient b_j=2^(-j), with FP32 grids and outputs. Source size and
bandwidth vary visible arithmetic and storage. Reference evaluation can
use exact rational polynomial arithmetic and a certified interval for
the exponential, converted directly from exact FP32 input values. This
is an arbitrary-precision host oracle, not a float64 GPU test. Refine the
interval until the unchanged original numerical gate is conclusively
decided; an unresolved interval is not a pass. Its evaluator and rounding
argument need independent review before native admission.

The minimal oracle panel contains one source fixture for each of the ten
family/inner rows. Select it from the same predeclared size/bandwidth
domain using its own source resource descriptor, near its own first
predicted crossing; do not transfer the nonlinear chain's crossing to
the linear source. Add an adjacent-size oracle witness only if the
coverage ledger otherwise lacks the required oracle-side crossing.
This adds ten independent numerical checks to the40 core/transfer
fixtures, without replacing any. The unchanged nonlinear chain,
Lorenz96, original Lorenz and Fabbri sources remain necessary scope.

Passing this oracle establishes numerical validity for the tested
default-flag image on that analytic source, not global solver accuracy.
Every selected default-flag policy is checked independently against the
oracle and separately against the unchanged cross-policy gate. An
oracle pass does not erase an original Lorenz/Fabbri cross-policy failure
or authorize a revised tolerance. A separate nonlinear oracle or
independently justified numerical contract is required to replace any
such unresolved numerical claim; the FMA-off diagnostic supplies neither.

The old pilot bank is permanently linked as exploration/diagnosis. Its
per-image repeated outputs are exact, but its strict cross-policy
failures remain failures. Its fastest times, native registers, counters
and measured aliases cannot select this cohort, prune its candidates or
supply final validation scores. Fresh evaluation of an already studied
identity is labelled a confirmatory rerun, not an unseen holdout.

The following are unavailable until the compact selector and its reviewed
source interface land: concrete crossing sizes/action pairs, final finite
candidate set, joint placement defaults, numerical score/order/tie
predictions, complete per-call/mask/cap coverage and the final frozen
manifest. A source feature inventory alone cannot fill those fields.
Missing opcode services, source allocation support or instruction/data
delivery assumptions must remain exact reasons in the descriptor.

The design can be instantiated only when those fields have actual
source-derived values and a verifier has checked the selector against
the original hardware-based specification. It makes no claim that the
minimum core proves every algorithm/tableau, mask regime or system. The
coverage ledger states the precise scope that the resulting evidence
can support.
