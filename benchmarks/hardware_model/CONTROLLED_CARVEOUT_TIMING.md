This is an ordinary timing diagnostic of one unchanged RK23 rolled/local
native image. It does not modify production, fit a predictor parameter,
or revise the original cross-candidate numerical failure. Every launch
must reproduce its own frozen state/status arrays exactly.

The runner retains the reviewed E5 original/diagnostic construction,
singleton equal-LTOIR callback carrier and strict cubin/SASS/resource gate.
It compiles each dispatcher once. One initial untimed functional launch
resolves and checks the actual CUlibrary/CUfunction at preference 16. All
subsequent work reuses that same function and native bytes. No factory,
dispatcher, compiled metadata or installed backend is patched.

Comparisons run in declared order B=0,8,32,64,100 with A=16. Each comparison
starts with a recorded but excluded ABBA ramp of four blocks, then eight
measured blocks ABBA BAAB. Every block contains 15 solves. Each block ends
with a uniform random idle of 1.5 to 3.5 seconds. Seed 20260905 and all
requested gaps are fixed before launch; actual gaps are retained. These
counts, orders and gaps are the frozen ab_gate.py defaults, not fitted
values. Each measured block statistic is the mean of its lowest five
CUDA-event times. Report all four paired percent changes and their median.
No significance or regression threshold is introduced.

Before a block, synchronize the stream, update only the preferred shared
memory attribute of the same resolved actual function, query it and its
unchanged resources, and query occupancy. Require at least two full waves
at that occupancy with the unchanged 2048 blocks of 128 threads and four
dynamic shared bytes. These are API observations. They do not prove the
physical partition or active resident-block count during execution. The
matched profile cohort's physical observations remain separate: a requested
percentage cannot be converted into an asserted physical partition.

For every solve, initialize input/output arrays, synchronize, construct the
launch arguments and configured launcher before recording the start CUDA
event. Record the end event immediately after the kernel submission in the
same stream, synchronize it and read its elapsed milliseconds. Memory
finalization, pending-copy waits, output copying, exact full-array checks,
driver queries, receipt writing, and idle gaps occur outside that interval.
Compilation and the initial function-loading warmup are also outside it.
The interval is a standard stream CUDA-event kernel interval; it is not a
claim that host submission latency can never leave the GPU idle between
event and kernel submissions.

All 900 block-launch samples, including 300 ramp samples, are retained at
the event API's full returned precision. Each launch is linked to a full
content-addressed state/status NPZ; duplicate complete outputs reuse the
same saved snapshot. Each launch independently compares every dtype,
shape and byte to the frozen reference. Disabled counters are checked
through the E5 source flags and exact placeholder contract. Failures stop
the run and remain saved, including failing snapshots and prior samples.
There is one initial warmup in addition to the 900 block launches.

CPU author checks exercise actual ab_gate order/constants, the deterministic
schedule and hand-computed summary arithmetic; they perform no compilation
or launch. Independent review precedes root-owned execution. No NCU process
may run concurrently with this ordinary timing bank.
