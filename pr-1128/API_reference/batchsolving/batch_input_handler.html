BatchInputHandler

Solver uses a BatchInputHandler to turn the initial values and parameters you pass to solve into the arrays the GPU reads, one row per variable and one column per run. The grid functions below build those arrays from dicts of values.

_fill_aligned(states_plan: dict, params_plan: dict, kind: str, backed: set, swept_set: ValuedSet, state_set: ValuedSet) → tuple[ndarray, ndarray][source]

Build the state and parameter arrays at a shared run count.

Generate a Cartesian product when kind is "combinatorial" and at least one input is a dict, varying the parameters most quickly. Otherwise, pair the columns run for run, using a single-run input in every run. Write each array straight into a policy-backed destination.

Parameters:

  • states_plan – Plan for the initial values.

  • params_plan – Plan for the swept parameter values.

  • kind – Grid type: “combinatorial” or “verbatim”.

  • backed – Identity set of destination arrays this call allocated.

  • swept_set – The swept parameters with their defaults.

  • state_set – The states with their default initial values.

Returns:

Aligned (states, params) arrays with matching run counts.

Return type:

tuple[ndarray, ndarray]

Raises:

ValueError – If the method pairs two inputs whose run counts differ with more than one run each, or kind is unknown.

set_swept_parameters(parameters: Dict | ArrayLike | None = None, fix_constant_parameters: bool = True) → object[source]

Set the system’s swept parameters to match a parameter input.

Pass None, an empty dict or an empty 1D array to compile every parameter in at its default. Name parameters in a dict, or give an array a row for every parameter. The handler compiles in each dict entry or row that holds one value and sweeps the others; pass fix_constant_parameters=False to sweep them all. Give any other array a row per parameter the system sweeps now; the handler keeps those parameters swept and compiles every other parameter in at its default. While the system sweeps one parameter, you can give its values as a 1D array with one value per run.

Parameters:

  • parameters – A dict, a host or device array, or None.

  • fix_constant_parameters – Compile in every dict entry and every row of a full-height host array that holds one value. Pass False to sweep them instead.

Returns:

The swept parameters’ values as a dict or an array with a row per swept parameter, or None when nothing is swept.

Return type:

object

Raises:

ValueError – If an array’s row count matches neither the swept parameters nor every parameter, or it has more than two dimensions. Also if the system sweeps one parameter and you pass a 1D array with the same number of values as the system has parameters, because the handler cannot tell one run from a sweep.

cubie.batchsolving.BatchInputHandler.combinatorial_grid(request: Dict[str | int, float | ArrayLike | ndarray], values_instance: ValuedSet, silent: bool = False) → tuple[ndarray, ndarray][source]

Build a grid of all unique combinations of requested values.

Parameters:

  • request – Dictionary keyed by parameter names or indices whose values are scalars or iterables describing sweep values. Value arrays may differ in length.

  • values_instance – variable set used to resolve indices for the provided keys.

  • silent – When True suppresses warnings about unrecognised keys.

Returns:

Pair of index and value arrays describing the combinatorial grid. Value array is in (variable, run) format.

Return type:

tuple of ndarray and ndarray

Notes

Unspecified parameters retain their defaults when the grid is later expanded. The number of runs equals the product of all supplied value counts.

Examples

>>> combinatorial_grid(
...     {"param1": [0.1, 0.2, 0.3], "param2": [10, 20]}, system.parameters
... )
(array([0, 1]),
 array([[ 0.1,  0.1,  0.2,  0.2,  0.3,  0.3],
        [10. , 20. , 10. , 20. , 10. , 20. ]]))
cubie.batchsolving.BatchInputHandler.verbatim_grid(request: Dict[str | int, float | ArrayLike | ndarray], values_instance: ValuedSet, silent: bool = False) → tuple[ndarray, ndarray][source]

Build a grid that aligns parameter rows without combinatorial expansion.

Parameters:

  • request – Dictionary keyed by parameter names or indices whose values are scalars or iterables describing sweep values.

  • values_instance – variable set used to resolve indices for the provided keys.

  • silent – When True suppresses warnings about unrecognised keys.

Returns:

Pair of index and value arrays describing the row-wise grid. Value array is in (variable, run) format.

Return type:

tuple of ndarray and ndarray

Notes

All value arrays must share the same length so rows stay aligned. verbatim_grid repeats an entry with a single value across every run.

Examples

>>> verbatim_grid(
...     {"param1": [0.1, 0.2, 0.3], "param2": [10, 20, 30]},
...     system.parameters,
... )
(array([0, 1]),
 array([[ 0.1,  0.2,  0.3],
        [10. , 20. , 30. ]]))
cubie.batchsolving.BatchInputHandler.unique_cartesian_product(arrays: List[ndarray]) → ndarray[source]

Return unique combinations of elements from input arrays.

Each input array can contain duplicates, but the output omits duplicate rows while preserving the order of the input arrays.

Parameters:

arrays – List of one-dimensional NumPy arrays containing elements to combine.

Returns:

Two-dimensional array in (variable, run) format where each column is a unique combination of the supplied values.

Return type:

ndarray

Notes

Duplicate elements are removed by constructing an ordered dictionary per input array. itertools.product then generates the Cartesian product of the deduplicated inputs.

Examples

>>> unique_cartesian_product([np.array([1, 2, 2]), np.array([3, 4])])
array([[1, 1, 2, 2],
       [3, 4, 3, 4]])
