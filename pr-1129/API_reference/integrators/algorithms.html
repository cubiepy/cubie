Algorithms

cubie.integrators.algorithms

To choose an algorithm, pass its name as algorithm= to Solver or as method= to solve_ivp(). Choosing an Algorithm helps you pick one and lists every name you can pass. This page gives the settings cubie uses with each algorithm unless you set them yourself, and lists the classes that implement the algorithms.

Default settings

You can pass the general name of a group of methods, such as "erk" or "dirk", and cubie uses the method in the table below. You can also pass the name of one method, such as "radau".

Step controller

CuBIE has default controllers tuned for each algorithm, which may not be ideal for your specific problem. You’ll find the default controller of every method in the tables in Choosing an Algorithm. To use a different controller, pass step_controller.

Cubie can only adapt the step size if it can estimate the error of each step. With a method that has no error estimate, cubie steps at a fixed size, and warns with a UserWarning if you ask for an adaptive controller. Cubie steps at a fixed size with the default dirk and firk methods, because they have no error estimate. To adapt the step, pick a method that has one, such as kvaerno3 or radau.

With an adaptive method, cubie limits how much the step can change from one step to the next:

When you use a method’s default controller, cubie also uses gains tuned for that method. With the ERK methods whose default controller is i, cubie uses integral_gain=1.2. With a DIRK method and the pi controller, cubie uses integral_gain=0.3 * (q + 1) / q and proportional_gain=0.4 * (q + 1) / q, where q is the lower of the method’s two orders. For kvaerno3, of order 3(2), these gains are 0.45 and 0.6. If you choose a different controller, cubie uses that controller’s own gains, listed in Solver Options.

Implicit solver settings

With backward Euler, Crank–Nicolson, DIRK and FIRK methods, cubie solves a nonlinear system at every step with Newton’s method, and a linear system for each Newton update. With Rosenbrock-W methods, cubie solves only the linear systems, so the Newton settings don’t apply to them. See Solver Options for what each setting does.

Base classes

  • BaseStepConfig – the settings that explicit and implicit steps share.

  • BaseAlgorithmStep – the base class of every step, which compiles the step in the chosen precision.

  • StepCache – the compiled step and its Newton solver, with the step’s order and sizes.

Explicit steps

  • ExplicitStepConfig – the settings of an explicit step.

  • ExplicitEulerStep – the forward Euler step.

  • ERKStep – the explicit Runge–Kutta step, for any ERK tableau.

  • ERK tableau registry – the named ERK methods, with references.

Implicit steps

  • ImplicitStepConfig – the settings of an implicit step, including its Newton and linear solver settings.

  • BackwardsEulerStep – the backward Euler step.

  • BackwardsEulerPCStep – the backward Euler step with a forward Euler predictor.

  • CrankNicolsonStep – the Crank–Nicolson step.

  • DIRKStep – the diagonally implicit Runge–Kutta step, for any DIRK tableau.

  • DIRK tableau registry – the named DIRK methods, with references.

  • FIRKStep – the fully implicit Runge–Kutta step, for any FIRK tableau, including Gauss–Legendre and Radau IIA.

  • FIRK tableau registry – the named FIRK methods, with references.

  • GenericRosenbrockWStep – the Rosenbrock-W step, for any Rosenbrock-W tableau.

  • Rosenbrock tableau registry – the named Rosenbrock-W methods, with references.

Factory function

  • get_algorithm_step – builds the step for an algorithm name or tableau.

Dependencies

Cubie builds the Newton and linear solvers of the implicit steps from cubie.integrators.matrix_free_solvers. Each step is a CUDAFactory, so cubie compiles it when it is first needed and caches the result. Cubie compiles each step with the system’s right-hand side, Jacobian products and observables, in the precision you choose for the solve.
