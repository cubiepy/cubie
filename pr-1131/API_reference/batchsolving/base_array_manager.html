BaseArrayManager

class cubie.batchsolving.arrays.BaseArrayManager.BaseArrayManager(precision: type = <class 'numpy.float32'>, sizes: ArraySizingClass | None = None, device: ArrayContainer = NOTHING, host: ArrayContainer = NOTHING, chunks: int = 0, stream_group: str = 'default', memory_proportion: float | None = None, memory_manager: MemoryManager = MemoryManager(totalmem=8589934592, registry={}, stream_groups=StreamGroups(groups={}, streams={}), _mode='passive', _auto_pool=[], _manual_pool=[], _queued_allocations={}, _group_chunk_parameters={}, _usage_clock=0, _pending_teardowns=[], pinned_max_bytes=8589934592, allocation_granule_bytes=33554432, _pinned_lock=<unlocked _thread.lock object>, _pinned_live_bytes=0, _pinned_releases=deque([]), _idle_pinned=[], _pinned_generation=0, _device_probe_error=None), memory_owner: object | None = None, num_runs: int = 1)[source]

Bases: ABC

Coordinate allocation and transfer for batch host and device arrays.

Parameters:

  • precision – NumPy floating type of the solve. The manager gives every floating-point array this dtype.

  • sizes – Expected shape of each managed array.

  • device (cubie.batchsolving.arrays.BaseArrayManager.ArrayContainer) – Container for device-side arrays.

  • host (cubie.batchsolving.arrays.BaseArrayManager.ArrayContainer) – Container for host-side arrays.

  • chunks – Number of chunks the batch is split into along the run axis.

  • stream_group – Name of the stream group to register in.

  • memory_proportion – Fraction of GPU memory this manager may use. Pass None to share the memory that no fraction claims equally with the other managers that give no fraction.

  • memory_manager – Memory manager that allocates the device arrays.

  • memory_owner – Object to register the manager’s allocations under. The memory manager evicts all of an owner’s allocations together. None registers the manager as its own owner.

  • num_runs (int) – Total number of runs in the batch.

Notes

Subclasses implement update() to attach a solve’s arrays, initialise() to copy a chunk’s data to the device before its launch, and finalise() to copy a chunk’s data back after it.

_update_host_array(new_array: NDArray, current_array: NDArray | None, label: str) → None[source]

Attach one incoming host array and record allocation needs.

Parameters:

  • new_array – Replacement array for the slot.

  • current_array – Previously stored host array or None.

  • label – Array name used to index tracking lists.

Raises:

ValueError – If new_array is None.

Notes

Incoming arrays are attached verbatim: the slot records the array’s actual backing (pinned, pageable, or memmap) and transfers read from it directly, so no copy is made. The one exception is a dtype mismatch, which is cast once into a fresh buffer. The solve reads input arrays when it runs — mutating a submitted array between solves changes what the next solve integrates.

allocate() → None[source]

Queue allocation requests for arrays that need reallocation.

Notes

loan_host_arrays(owner: object) → None[source]

Hand every host buffer to owner, emptying the slots.

owner is a result object that already references the arrays, and it keeps the data for as long as it lives. If it has been garbage collected by the next solve, the manager puts the buffers back in their slots and reuses them. Otherwise the next solve allocates new buffers.

Parameters:

owner – Object to hand the buffers to. The manager holds only a weak reference to it.

num_runs: int
reclaim_or_release_loan() → None[source]

Recover loaned host buffers if their owner was collected.

If the owner is still alive, forget the loan, so the buffers belong to the owner alone and the next transfer allocates new ones. If the owner has been collected, return the buffers to their slots for reuse. The manager tracks only the owner, so cubie overwrites, in the next solve, any of these arrays that other code kept after the owner was collected.

register_with_memory_manager() → None[source]

Register this manager with its memory manager.

Register _invalidate_hook() and _on_allocation_complete() as the manager’s callbacks. Attach a finalizer that, once the manager is garbage collected, queues the release of its registration and its buffers.
