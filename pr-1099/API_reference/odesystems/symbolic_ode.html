Bases: BaseODE

Symbolic representation of an ODE system.

The system holds a ParsedSystem, with every parameter left as a symbol, and a SystemSpecialiser child that assembles it for the parameters the current batch compiles.

Parameters:

  • parsed_system – Parsed system with every parameter left as a symbol.

  • precision – Target floating-point precision used for generated kernels.

  • name – Identifier used for generated modules.

  • operation_ordering – Generated-operation ordering policy.

  • swept_parameters – Names of the parameters that vary between the runs of a batch. Every other parameter is compiled in at its default value, and when you leave this out every parameter is compiled in. A solve sets the swept parameters to match its inputs, so giving them here saves specialising the system again at the first solve, which can take 10-100 ms.

Parse user inputs and instantiate a SymbolicODE.

Parameters:

  • dxdt – System equations defined as a single string, an iterable of equation strings in lhs = rhs form, or a Python callable with a (t, y, ...) signature.

  • states – State labels either as an iterable or as a mapping to default initial values.

  • observables – Observable variable labels to expose from the generated system.

  • parameters – Parameter labels either as an iterable or as a mapping to default values.

  • drivers – Names of the drivers you supply at solve time, as a list, or as a dict whose keys are the names. create reads only the keys.

  • user_functions – Custom callables referenced within dxdt expressions.

  • user_function_derivatives – Mapping of user-function names to callables evaluating their analytic derivatives, used when generating Jacobian-based solver helpers. A value may also be a list of callables evaluating the first, second, … derivatives; the order-n callable takes the function’s arguments followed by n argument indices.

  • name – Identifier used for generated files. Defaults to unnamed_ followed by the start of a hash of the equations.

  • precision – Target floating-point precision used when compiling the system.

  • strict – When True require every symbol to be explicitly categorised.

  • state_units – Optional units for states. Defaults to “dimensionless”.

  • parameter_units – Optional units for parameters. Defaults to “dimensionless”.

  • observable_units – Optional units for observables. Defaults to “dimensionless”.

  • driver_units – Optional units for drivers. Defaults to “dimensionless”.

  • state_priority – Per-unknown state-selection priorities (higher values are preferred as solver states).

  • irreducible – Unknowns that must not be eliminated.

  • simplify_options – Extra keyword arguments forwarded to structural_simplify().

  • operation_ordering – Generated-operation ordering policy: "liveness_auto", "kahn", "greedy", or "dfs". Defaults to CUBIE_OPERATION_ORDERING.

  • swept_parameters – Names of the parameters that vary between the runs of a batch. Every other parameter is compiled in at its default value, and when you leave this out every parameter is compiled in. A solve sets the swept parameters to match its inputs, so giving them here saves specialising the system again at the first solve, which can take 10-100 ms.

Returns:

Fully constructed symbolic system ready for compilation.

Return type:

SymbolicODE
